# Ask V Work Hub capability matrix

Task 7 contract, September 24, 2026. Applies to typed Ask V and realtime tool execution. Tool discovery is not authorization: every request uses the current authenticated session and canonical domain endpoint. `work-hub/context-access.ts` and the resource-specific capability projection are authoritative; client roles never grant an action.

## Shared execution boundaries

- Registered Work Hub and Implementation A tools use one metadata resolver. Writes require the server's exact-argument confirmation flow. The active organization is bound from the session, not model-supplied owner values. Unsupported actions fail closed.
- Domain endpoints recheck role, membership, current resource access and policy. Asset custody preserves `confirmed: true` on the canonical wire request after server confirmation; arbitrary supplied confirmation fields do not bypass Ask V confirmation.
- Mutation operation IDs and domain version checks are retained. Asset conflict/blocked results are explicitly unsuccessful. A replay returns the saved domain outcome; changed-value reuse, stale versions, revocation and holds are not reported as success.
- Ask V audit records retain document/file, asset, station, channel, task, occurrence and export IDs, including returned IDs on creation. Endpoint-level command/audit receipts remain authoritative; a preview may have no persisted target ID.
- A link never grants access. Shared exact destinations accept supported record types and UUIDs only. Web readers fetch the canonical record with the current session; native navigation preflights the same read, verifies that the account scope has not changed, and the destination loads it again. Unknown/revoked records do not fall back to an unrelated list item.
