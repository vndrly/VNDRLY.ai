# AskV voice fidelity follow-up

The September 7 web test exposed two distinct failures: unrelated speech
transcripts and a confirmation loop rejecting ordinary replies such as
"I confirm" and "Yes, confirm". Microphone quality cannot be diagnosed from
the exported text alone.

## Behavior

- Web AskV shows a microphone selector, the input currently in use and a live
  level meter. Selection is saved only in this browser and applies on the next
  listening start; mute/unmute applies it. Realtime, wake capture and fallback
  recording use the same selection. A missing selected input falls back to the
  system default with a visible notice. Permission denial does not retry.
- Enumeration does not request microphone access. The meter uses the existing
  stream or wake frames, retains only a scalar level, and cleans up on capture
  shutdown. Muting also stops fallback recording. Across VNDRLY retains its
  existing foreground conversation behavior when the panel closes.
- Clear English and Spanish confirmation replies are recognized as whole
  phrases. Questions, negation, ambiguous fragments and requests to change the
  proposed action do not approve it. Approval still requires the exact pending
  action and a later saved user turn; account permissions are unchanged.
- iOS retries recover the server's pending action key for unchanged arguments,
  rather than requiring the model to repeat a key. Device GPS remains fixed
  through approval and cannot be replaced by coordinates generated by the model.
- The existing OpenAI connection retains `gpt-4o-mini-transcribe`, with the saved account
  language (English fallback), field-operation terminology, near-field noise
  reduction, and semantic turn detection with medium eagerness. These settings
  guide language recognition and let users finish sentences across short pauses.
  No provider was added.
- Voice instructions distinguish unclear audio, a pending confirmation, and
  actual permission denial. "Can you hear me?" never approves a pending action.
  AskV must not claim an action succeeded before its tool reports success.

## Verification and remaining device check

Focused tests cover confirmation binding and replay, speech-setting propagation,
microphone selection and cleanup, missing-device fallback, and mobile GPS
approval retries. The actual provider accepted the English and Spanish session
configurations. A controlled comparison of four clean synthetic English clips
(41 reference words, the same language and terminology guidance) yielded zero
word edits with mini and two with the larger transcriber ("north site" became
"Northside"). This small fixture did not justify a model switch; it is not a
general accuracy benchmark. Required integration and browser gates run on a fresh local
database in release CI; no existing database is reset.

After the release, open AskV in the web app, choose the wired headset, then
mute/unmute. Confirm the displayed current input is the headset and that the
meter moves when speaking. Try a full sentence with a short pause and an
ordinary "I confirm" reply to a stated action. If recognition remains poor,
compare the same sentence with the system-default microphone. Automated tests
do not establish acoustic accuracy for the user's particular headset or room.

and [semantic turn detection](https://platform.openai.com/docs/api-reference/realtime-server-events/input_audio_buffer/committed?lang=node).
